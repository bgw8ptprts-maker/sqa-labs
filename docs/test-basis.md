# Test Basis: KIUT Elective Course Registration Portal

## 1. Цель

Определить источники требований, объекты тестирования и условия, на основании которых разрабатываются тестовые условия для портала записи на элективные курсы KIUT.

## 2. Источники тестового базиса

### 2.1. Документы
- Требования REQ-01–REQ-08.
- Техническое задание и спецификация системы.
- Правила записи на элективные курсы.
- Макеты и прототипы интерфейса.
- Спецификация API.
- Политика обработки персональных данных.
- Документация по инфраструктуре и развёртыванию.

### 2.2. Люди и заинтересованные стороны
- Владелец продукта: подтверждает бизнес-требования и приоритеты.
- Представитель учебного отдела: уточняет правила записи и ограничения.
- Разработчик: разъясняет реализацию и интерфейсы компонентов.
- Системный администратор: предоставляет сведения о доступности и инфраструктуре.
- Специалист по информационной безопасности: определяет требования к защите данных.
- Студенты: участвуют в оценке удобства использования.

### 2.3. Стандарты и нормативные документы
- ISO/IEC 25010:2023: модель качества продукта.
- Применимые нормативные требования Узбекистана к персональным данным.
- Внутренние стандарты разработки, тестирования и информационной безопасности.

## 4. Основные тестовые условия

### REQ-01
- Запись на первый, второй и третий курсы разрешена.
- Запись на четвёртый курс отклоняется.
- После отказа данные остаются согласованными.

### REQ-04
- Пароль короче 8 символов отклоняется.
- Пароль длиной 8 символов с цифрой принимается.
- Пароль длиной 20 символов с цифрой принимается.
- Пароль длиннее 20 символов отклоняется.
- Пароль без цифр отклоняется.

### REQ-08
- При отсутствии мест отображается «Мест нет».
- Запись при отсутствии мест не создаётся.
- Запись при наличии свободного места разрешается.
- При конкурентных запросах последнее место не выдаётся двум студентам.

## 5. Критерии качества

- Производительность: не менее 95% запросов завершаются за 2 секунды при нагрузке 300 одновременных пользователей.
- Удобство использования: не менее 90% из 20 участников выполняют заданный сценарий за 3 минуты без помощи.
- Доступность: не менее 99,5% за 30-дневный месяц.
- Безопасность: проверка передачи данных и контроля доступа.
- Совместимость: успешный согласованный набор тестов в двух последних стабильных версиях каждого указанного браузера.

## 6. Ограничения и допущения

- Предложенные численные значения являются учебными критериями до согласования с заказчиком.
- Точные версии браузеров и тестовые устройства фиксируются перед тестированием.
- Для нагрузочных испытаний используется согласованная тестовая среда.
- Тестовые данные должны быть синтетическими либо надлежащим образом обезличенными.
- Доступность рассчитывается по согласованной методике с явно определёнными исключениями.

## 7. Трассируемость

Каждое требование должно быть связано хотя бы с одним тестовым условием. Для полноценной трассируемости каждому условию назначается идентификатор тест-кейса и фиксируется результат выполнения.

Предварительное покрытие требований тестовыми условиями: 8 / 8 = 100%.
