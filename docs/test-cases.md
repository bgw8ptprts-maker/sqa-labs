# Тестирование модуля регистрации

## 1. Тестовые условия

Приоритеты: P1 — высокий, P2 — средний, P3 — низкий.

| ID | Тестовое условие | Требование | Приоритет |
|---|---|---|---|
| C01 | Логин длиной 4 символа принимается | R1 | P1 |
| C02 | Логин длиной 16 символов принимается | R1 | P2 |
| C03 | Логин короче 4 символов отклоняется | R1 | P1 |
| C04 | Логин с недопустимыми символами отклоняется | R1 | P1 |
| C05 | Пароль с заглавной буквой и цифрой принимается | R2 | P1 |
| C06 | Пароль без заглавной буквы отклоняется | R2 | P1 |
| C07 | Пароль без цифры отклоняется | R2 | P1 |
| C08 | Пароль короче 8 символов отклоняется | R2 | P1 |
| C09 | Пароль длиннее 20 символов отклоняется | R2 | P1 |
| C10 | Email с одним @ и точкой в домене принимается | R3 | P1 |
| C11 | Email без @ отклоняется | R3 | P1 |
| C12 | Email с двумя символами @ отклоняется | R3 | P1 |
| C13 | Возраст 16 лет принимается | R4 | P1 |
| C14 | Возраст 60 лет принимается | R4 | P2 |
| C15 | Возраст вне диапазона 16–60 отклоняется | R4 | P1 |
| C16 | Возраст, переданный строкой, отклоняется | R4 | P1 |
| C17 | Повторный логин отклоняется | R5 | P1 |
| C18 | При нескольких ошибках сообщаются все неверные поля | R6 | P1 |

## 2. Тест-кейсы

Общие предусловия: модуль регистрации доступен, функция `validate_registration` импортируется, тестовые данные подготовлены. Для TC-REG-009 в `USERS` присутствует логин `existing_user`.

| ID | Название | Приоритет | Требование |
|---|---|---|---|
| TC-REG-001 | Успешная регистрация | P1 | R1, R2, R3, R4 |
| TC-REG-002 | Слишком короткий логин | P1 | R1, R6 |
| TC-REG-003 | Пароль без заглавной буквы | P1 | R2, R6 |
| TC-REG-004 | Пароль без цифры | P1 | R2, R6 |
| TC-REG-005 | Пароль короче 8 символов | P1 | R2, R6 |
| TC-REG-006 | Пароль длиной 21 символ | P1 | R2, R6 |
| TC-REG-007 | Email без символа @ | P1 | R3, R6 |
| TC-REG-008 | Возраст меньше 16 лет | P1 | R4, R6 |
| TC-REG-009 | Повторная регистрация логина | P1 | R5, R6 |
| TC-REG-010 | Ошибки в нескольких полях | P1 | R1, R2, R3, R6 |

### TC-REG-001: Успешная регистрация

- **Приоритет:** P1
- **Требования:** R1, R2, R3, R4
- **Предусловия:** логин `ali_01` отсутствует в `USERS`.
- **Шаги:** вызвать `validate_registration` с указанными данными.
- **Тестовые данные:** `login="ali_01"`, `password="Secret2026"`, `email="ali@kiut.uz"`, `age=20`.
- **Ожидаемый результат:** возвращается пустой список `[]`.

### TC-REG-002: Слишком короткий логин

- **Приоритет:** P1
- **Требования:** R1, R6
- **Предусловия:** модуль доступен.
- **Шаги:** вызвать функцию с логином из 3 символов.
- **Тестовые данные:** `"ali"`, `"Secret2026"`, `"ali@kiut.uz"`, `20`.
- **Ожидаемый результат:** список ошибок содержит `Логин должен содержать от 4 до 16 символов`.

### TC-REG-003: Пароль без заглавной буквы

- **Приоритет:** P1
- **Требования:** R2, R6
- **Предусловия:** остальные поля корректны.
- **Шаги:** передать пароль без заглавных букв.
- **Тестовые данные:** `"ali_02"`, `"secret2026"`, `"ali2@kiut.uz"`, `20`.
- **Ожидаемый результат:** список ошибок содержит `Пароль должен содержать заглавную букву`.

### TC-REG-004: Пароль без цифры

- **Приоритет:** P1
- **Требования:** R2, R6
- **Предусловия:** остальные поля корректны.
- **Шаги:** передать пароль без цифр.
- **Тестовые данные:** `"ali_03"`, `"SecretWord"`, `"ali3@kiut.uz"`, `20`.
- **Ожидаемый результат:** список ошибок содержит `Пароль должен содержать цифру`.

### TC-REG-005: Пароль короче 8 символов

- **Приоритет:** P1
- **Требования:** R2, R6
- **Предусловия:** остальные поля корректны.
- **Шаги:** передать пароль длиной 4 символа.
- **Тестовые данные:** `"ali_04"`, `"Sec1"`, `"ali4@kiut.uz"`, `20`.
- **Ожидаемый результат:** список ошибок содержит `Пароль должен содержать от 8 до 20 символов`.

### TC-REG-006: Пароль длиной 21 символ

- **Приоритет:** P1
- **Требования:** R2, R6
- **Предусловия:** остальные поля корректны.
- **Шаги:** передать пароль длиной 21 символ.
- **Тестовые данные:** `"ali_05"`, `"SecretWord12345678901"`, `"ali5@kiut.uz"`, `20`.
- **Ожидаемый результат:** список ошибок содержит `Пароль должен содержать от 8 до 20 символов`.

### TC-REG-007: Email без символа @

- **Приоритет:** P1
- **Требования:** R3, R6
- **Предусловия:** остальные поля корректны.
- **Шаги:** передать email без символа `@`.
- **Тестовые данные:** `"ali_06"`, `"Secret2026"`, `"ali.kiut.uz"`, `20`.
- **Ожидаемый результат:** список ошибок содержит `Email должен содержать один @ и домен с точкой`.

### TC-REG-008: Возраст меньше 16 лет

- **Приоритет:** P1
- **Требования:** R4, R6
- **Предусловия:** остальные поля корректны.
- **Шаги:** передать возраст 15.
- **Тестовые данные:** `"ali_07"`, `"Secret2026"`, `"ali7@kiut.uz"`, `15`.
- **Ожидаемый результат:** список ошибок содержит `Возраст должен быть целым числом от 16 до 60`.

### TC-REG-009: Повторная регистрация логина

- **Приоритет:** P1
- **Требования:** R5, R6
- **Предусловия:** `USERS` содержит `existing_user`.
- **Шаги:** передать существующий логин с остальными корректными полями.
- **Тестовые данные:** `"existing_user"`, `"Secret2026"`, `"new@kiut.uz"`, `20`.
- **Ожидаемый результат:** список ошибок содержит `Такой логин уже существует`.

### TC-REG-010: Ошибки в нескольких полях

- **Приоритет:** P1
- **Требования:** R1, R2, R3, R6
- **Предусловия:** модуль доступен.
- **Шаги:** передать одновременно неверный логин, пароль и email.
- **Тестовые данные:** `"ab-"`, `"secret"`, `"wrong-email"`, `20`.
- **Ожидаемый результат:** список содержит ошибки логина, пароля и email. Проверяются все три поля, а не только первое обнаруженное нарушение.

## 4. Расчёт покрытия требований

Формула:

Creq = (Количество покрытых требований / Общее число требований) × 100%

В матрице покрыты все требования R1–R6:

Creq = (6 / 6) × 100% = 100%

**Результат:** покрытие требований тест-кейсами составляет 100%.

Это не означает, что проверены все возможные комбинации и граничные значения. Для расширения покрытия тестами следует дополнительно проверить логин длиной 4 и 16 символов, возраст 16 и 60 лет, email с двумя символами @ и возраст, переданный строкой.
